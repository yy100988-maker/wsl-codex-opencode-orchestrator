## 字段说明

| 路径 | 说明 | 建议 |
|---|---|---|
| `wsl.distro_name` | 明确的 WSL2 发行版名 | 不依赖默认发行版 |
| `wsl.project_root` | WSL Linux 项目根目录 | 优先 `/home/...`，避免高并发使用 `/mnt/d` |
| `wsl.source_project_root` | Windows 交付镜像的 WSL 路径 | 只用于受控状态导出，不作为并行 worktree 根目录 |
| `wsl.auto_install_opencode` | 缺失或检测到 wrapper 时自动安装 Linux OpenCode | 默认 `true` |
| `wsl.opencode_version` | 可选的安装版本约束 | 空值表示安装器默认版本 |
| `wsl.auto_install_project_dependencies` | 发现 pnpm 依赖树缺失或悬空链接时自动执行 frozen install | 默认 `true` |
| `agent.provider` | 子 agent 提供方：`opencode` 或 `grok` | 默认 `opencode` |
| `grok.grok_path` | Grok CLI 可执行文件路径（Windows 侧） | 不写死，按实际安装位置配置 |
| `models.implementation` | 默认实现模型 | `opencode-go/mimo-v2.5` |
| `models.fallback` | 主模型不可用时的唯一回退 | `opencode-go/hy3` |
| `models.last_resort` | 备用模型仍失败时的兜底模型；Grok 模式默认 `big-pickle` | 可选，默认空 |
| `scheduler.max_concurrent_agents` | 最大同时运行任务数 | 不超过 100，并受内存限制 |
| `scheduler.monitor_interval_seconds` | 调度检查周期 | 默认 30 秒 |
| `scheduler.orphan_scan_interval` | 孤儿进程扫描周期（每 N 轮触发一次） | V2.2 新增，默认 5，最小 1 |
| `scheduler.health_check_interval` | 进程健康采样周期 | V2.2 新增，默认 1 轮 |
| `scheduler.disk_recovery_interval` | 磁盘回收检查周期 | V2.2 新增，默认 10 |
| `scheduler.event_compress_interval` | 事件压缩执行周期 | V2.2 新增，默认 100 |
| `scheduler.max_task_runtime_seconds` | 单任务最大运行时间 | 默认 3600 秒 |
| `scheduler.stall_timeout_seconds` | 日志无进展超时 | 默认 300 秒 |
| `scheduler.health_stall_timeout_seconds` | 健康监控日志无进展超时 | V2.2 新增，默认 600 秒 |
| `scheduler.health_warning_persist_threshold` | 连续 warning 轮数阈值，超过后触发 persistent 告警 | V2.2 新增，默认 2 |
| `scheduler.cpu_high_percent` | CPU 高占用判定百分比 | V2.2 新增，默认 90 |
| `scheduler.cpu_high_duration_seconds` | CPU 高占用持续时间阈值 | V2.2 新增，默认 300 |
| `memory.*` | WSL/Windows 双层内存阈值 | 停止阈值高于恢复阈值 |
| `memory.wsl_max_mb` | WSL cgroup 内存上限 | V2.2 新增，默认 8192 |
| `memory.wsl_swap_mb` | WSL cgroup swap 限制 | V2.2 新增，默认 2048 |
| `memory.cgroup_enabled` | 是否启用 WSL cgroup 内存限制 | V2.2 新增，默认 true |
| `memory.pressure_levels` | 内存压力等级阈值（level1 < level2 < level3 < level4） | V2.2 新增，默认 70/80/85/90 |
| `memory.concurrency_reduction` | 各等级并发降级比例（level1/2/3 > 0, level4 = 0） | V2.2 新增，默认 0.7/0.4/0.1/0 |
| `memory.memory_cleanup` | Level 3/4 高内存清理配置 | V2.2 新增 |
| `memory.memory_cleanup.level3_kill_count` | Level 3 触发时清理任务数 | V2.2 新增，默认 1 |
| `memory.memory_cleanup.level4_kill_count` | Level 4 触发时清理任务数 | V2.2 新增，默认 2 |
| `memory.memory_cleanup.kill_above_percent` | 仅清理 RSS 超过此百分比的任务 | V2.2 新增，默认 85 |
| `memory.memory_cleanup.dry_run` | 仅记录候选列表不执行清理 | V2.2 新增，默认 false |
| `memory.health_growth_window_seconds` | 内存增长采样窗口 | V2.2 新增，默认 300 秒 |
| `memory.health_growth_mb` | 窗口内内存增长超过此值触发 warning | V2.2 新增，默认 200 MB |
| `disk_recovery.enabled` | 是否启用磁盘回收 | V2.2 新增，默认 true |
| `disk_recovery.threshold_mb` | .opencode 目录超过此大小触发回收 | V2.2 新增，默认 1024 MB，最小 256 MB |
| `disk_recovery.archive_max_age_days` | 已完成任务归档保留天数 | V2.2 新增，默认 30 天 |
| `disk_recovery.failed_archive_max_age_days` | 失败任务归档保留天数 | V2.2 新增，默认 7 天 |
| `disk_recovery.delete_completed_worktrees` | 回收时是否删除已完成的受控 worktree | V2.2 新增，默认 true |
| `event_compress.enabled` | 是否启用事件压缩 | V2.2 新增，默认 true |
| `event_compress.full_keep_days` | 保留完整 JSONL 的天数 | V2.2 新增，默认 7，必须 < summary_start_days |
| `event_compress.summary_start_days` | 开始生成摘要的天数 | V2.2 新增，默认 7，必须 <= archive_after_days |
| `event_compress.archive_after_days` | 归档到 archives 目录的天数 | V2.2 新增，默认 30 |
| `event_compress.archive_dir` | 归档文件存放目录 | V2.2 新增，默认 `.opencode/archives/events` |
| `cleanup.term_grace_seconds` | SIGTERM 等待时间 | 默认 15 秒 |

## 阈值规则

- 任一侧内存达到 `stop_admission_percent`：停止新增任务。
- 任一侧达到 `critical_percent`：优先清理已结束任务和处理 Gate。
- 两侧都低于恢复阈值：恢复任务准入。
- Windows 主机必须保留 `windows_reserve_mb` 可用内存。

## V2.2 内存压力等级

内存压力按 `pressure_levels` 阈值划分为 Level 0-4：

| Level | 条件 | 动作 |
|---|---|---|
| 0 | `< level1_percent` | 全额并发 |
| 1 | `< level2_percent` | 并发 × `concurrency_reduction.level1`（至少 1） |
| 2 | `< level3_percent` | 并发 × `concurrency_reduction.level2`（至少 1） |
| 3 | `< level4_percent` | 并发 × `concurrency_reduction.level3`（至少 1），触发高内存清理 |
| 4 | `>= level4_percent` | 并发 = 0，停止准入，触发高内存清理 |

调度器使用 `max(wsl_used_percent, host_used_percent)` 作为压力输入。

## V2.2 配置校验

`scripts/read-config.sh` 集中执行 V2.2 配置校验与默认值补齐：

1. 读取 `.opencode/wsl-config.json`（缺失时使用空对象）。
2. 深度合并 V2.2 默认值。
3. 执行校验规则：
   - `memory.pressure_levels.level1 < level2 < level3 < level4`
   - `memory.concurrency_reduction.level1/2/3 > 0` 且 `level4 == 0`
   - `scheduler.orphan_scan_interval >= 1`
   - `disk_recovery.threshold_mb >= 256`
   - `event_compress.full_keep_days < summary_start_days <= archive_after_days`
4. 非法配置输出警告并回退默认值；涉及安全边界时 fail-closed。
5. 输出 canonical JSON 供脚本以 `jq` 读取。

## 安全建议

- 不把 API key、token 或 cookie 写入配置文件。
- 不把 `.opencode/` 运行日志直接提交到公开仓库。
- 不把 `project_root` 指向不受控的共享目录。
- 默认要求 Git 工作区干净；脏工作区必须先建立 baseline，或显式设置 `wsl.allow_dirty_project=true`。
- 修改模型前先用 `opencode models`（OpenCode 模式）或 `grok models`（Grok 模式）和一次最小请求验证可用性。
