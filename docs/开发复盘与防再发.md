# WSL 版开发复盘与防再发

> 日期：2026-08-22
> 范围：WSL 版 V2.2 开发全过程
> 对照：[Windows 版开发复盘与防再发](../codex-opencode-orchestrator/docs/开发复盘与防再发.md) / [[../codex-opencode-orchestrator/docs/开发复盘与防再发.md]]

## 1. 复盘背景

本次目标是根据 V2.2详细设计方案驱动 WSL 版 V2.2 开发，由 opencode 执行子任务（A-G），最终推送到 GitHub。实际推进中在环境适配、agent 权限、merge 策略等方面遇到多个系统性问题。

## 2. 遇到的坑

### 2.1 opencode CLI 参数格式不一致

- SKILL.md 写 opencode run --model <model> --format json --file <prompt>。
- 实际 --file 附加文件后，positional args 被当成文件名解析，报 File not found。
- 去掉 --file 只传 positional message 时报 You must provide a message or a command。
- 最终方案：opencode run --model <model> --message "<prompt_content>"。

### 2.2 opencode 权限弹窗阻塞子任务

- opencode 对 xternal_directory 默认拒绝，触发 permission requested: external_directory; auto-rejecting。
- 子 agent 读取 docs/ 目录时被卡住，长时间无输出。
- 没有 --auto 参数或 permission_mode 配置来绕过。

### 2.3 .opencode-handoff.json 多分支 merge 冲突

- d/e 子任务都提交了 .opencode-handoff.json 到各自的分支。
- 主分支 merge 时出现 CONFLICT (add/add)，需要手工解决。
- gate-runner.sh 在 changed_files 中排除了 handoff，但没阻止 git add。

### 2.4 core.quotepath 导致 Gate 中文路径不匹配

- gate-runner.sh 的 git diff --name-only 输出了 C-style 转义路径。
- handoff 中 changed_files 是 UTF-8 文件名，scope 检查永远不匹配。
- 修复后 pass。

### 2.5 子任务合并后执行权限位丢失

- B 子任务合并后，scripts/*.sh 执行权限从 wxr-xr-x 退化成 w-r--r--。
- Supervisor 启动时报 Permission denied。
- 需要手动 chmod +x scripts/*.sh 并提交修复。

### 2.6 leases.json schema 校验误报

- lease-manager 报 jq: error Cannot index string with string "files"。
- 实际 leases.json 为空数组 []，后续操作正常执行。
- 原因是 jq -e ... /dev/null 在某些 jq 版本下行为异常。
- 已修复为 jq -ne ... >/dev/null。

### 2.7 Shell 变量被 PowerShell 劫持

- wsl.exe -- bash -c 'for f in tests/*.sh; do echo ; done' 中 $f 被 PowerShell 展开为空。
- 	ests/*.sh glob 也偶尔不展开。
- 导致语法检查和文件遍历反复失败。

### 2.8 Supervisor 状态 history 为空导致依赖判断失败

- 手工 merge 了 A-E 任务后，orchestrator-state.json 的 history 为空。
- F 任务的 depends_on 基于 history done，但 history 为空，所以 F 永远不被调度。
- 需要手动补写 history entries。

### 2.9 opencode 超时无反馈

- opencode 进程在等待权限确认或读取大文件时，没有超时终止。
- Supervisor 的 stall_timeout_seconds 只检查日志修改时间，不检查 opencode 内部状态。
- 最终手动 kill 进程。

### 2.10 Start-Sleep 会话阻塞

- xec_command 的 yield_time_ms 机制在 WSL 命令上不可靠。
- Start-Sleep 的 PowerShell 会话可能阻塞 70+ 秒才返回。
- 导致大量重复的"等待计时器完成"输出。

### 2.11 .opencode/ 运行时状态不干净

- 多次需要清理 orchestrator-state.json、leases.json、锁文件。
- Supervisor 重启时残留的 supervisor.lock 阻止新实例启动。

## 3. 与 Windows 版对照

| Windows 版问题 | WSL 版是否存在 | 严重程度 | 根因差异 |

## 4. 优化建议

### 4.1 opencode CLI 兼容检查

- 启动前执行 opencode run --help，记录实际支持的参数格式。
- 根据实际 CLI 能力生成启动命令。
- SKILL.md 中明确正确调用方式。

### 4.2 抽离 Agent 启动器

- 新增 scripts/agent-launcher.sh，封装 probe/start/health。
- dmission-cycle.sh 只调用统一接口。

### 4.3 增加 opencode 自动审批

- 在 wsl-config.json 中添加 "agent": {"permission_mode": "acceptEdits"}。
- 在 process-manager.sh start 中加入 --auto 参数。

### 4.4 handoff 文件路径唯一化

- 修改 handoff 文件路径为 .opencode-handoff-{task_id}.json。
- 或在 .gitignore 中排除 .opencode-handoff.json。

### 4.5 合并后自动恢复权限位

- 添加 post-merge hook：chmod +x scripts/*.sh tests/*.sh。
- 在 .gitattributes 中标记 *.sh -merge。

### 4.6 PowerShell 调 WSL 规范

- 所有 WSL 调用统一用临时 .sh 脚本文件。
- 所有 WSL 脚本中使用 ${var:?} 代替 $var。

### 4.7 Supervisor 状态一致性保护

- 新增 scripts/state-reset.sh 工具。
- 在 admission-cycle 中增加 	asks.status 作为 fallback 判断依据。

### 4.8 opencode 超时保护

- 在 opencode 启动命令中加入 timeout 参数。
- 添加 permission denied 连续计数器。

### 4.9 文档与实现同步

- SKILL.md 中每个能力声明旁边标注"已实现/未实现"。
- 新增 	ests/provider-compatibility.sh。

## 6. V0.1.x 后续修复记录

> 日期：2026-08-22
> 版本起点：V0.1.0，当前 V0.1.2

### 6.1 Grok CLI 文档同步

- 原 SKILL.md 将 Grok CLI 命令写为 `grok agent --cwd --prompt-file --output-format streaming-json`，与实际 CLI 不匹配。
- 已修正为 `grok --cwd --prompt-file --output-format json --no-subagents --permission-mode auto --max-turns 30`；明确主命令是 `grok`，`grok agent` 是子命令。
- 模型名由不存在的 `grok-4` 修正为 `grok-4.6`，回退模型 `mimo-v25`。
- Grok 安装路径改为 `.opencode/wsl-config.json` 的 `grok.grok_path` 配置，不再写死路径。

### 6.2 智能路由

- 任务数 <= 6：主控直接编码，不创建 tasks.json、不启动 Supervisor。
- 任务数 > 6：进入完整 WSL 子 agent 调度流程。
- 直接编码模式使用 `.opencode/direct-mode.json` 记录状态，仍需生成开发完成报告和测试验收报告。

### 6.3 版本管理规则

- 每次更新代码或文档后只递增第三位：`0.1.0` -> `0.1.1` -> `0.1.2`。
- 第二位和第一位仅在用户显式要求时升级。
- 发版流程：更新 SKILL.md 的 `version` 字段 -> 提交 -> 打 tag `vX.Y.Z` -> 推送 GitHub -> 同步本地 skill。
