## 安装模式

运行时始终由 WSL2 中的 Supervisor 和 Linux OpenCode 执行。本安装层只负责从 Git 下载相同版本的运行时，并让宿主 Agent 平台读取同一份 `SKILL.md`。

| 平台 | 默认目标 | 安装模式 |
| --- | --- | --- |
| Codex | `~/.codex/skills` | 原生 Skill |
| Claude Code | `~/.claude/skills` | 原生 Skill |
| OpenCode | `~/.config/opencode/skills` | 原生 Skill |
| Trae | `~/.local/share/wsl-codex-opencode-orchestrator/trae` | 外部适配器 |
| Qoder | `~/.local/share/wsl-codex-opencode-orchestrator/qoder` | 外部适配器 |
| Grok CLI | `~/.local/share/wsl-codex-opencode-orchestrator/grok-cli` | 外部适配器 |
| WorkBuddy | `~/.local/share/wsl-codex-opencode-orchestrator/workbuddy` | 外部适配器 |

外部适配器不会猜测第三方客户端的私有配置目录。若该客户端提供实际 Skill 目录，Agent 安装时必须传入 `--target-root`。

## Agent 自动安装

用户可让任意支持本地 Shell 的 Agent 在 WSL 中执行：

```bash
git clone --depth 1 https://github.com/yy100988-maker/wsl-codex-opencode-orchestrator.git /tmp/wsl-orchestrator
bash /tmp/wsl-orchestrator/scripts/install-skill.sh --platform codex
rm -rf /tmp/wsl-orchestrator
```

将 `codex` 替换为 `claude-code`、`opencode`、`trae`、`qoder`、`grok-cli` 或 `workbuddy`。也可使用下载后自动清理临时 checkout 的 Bootstrap：

```bash
bash scripts/bootstrap-install.sh --platform claude-code
```

Trae、Qoder、Grok CLI、WorkBuddy 已知 Skill 目录时，使用显式目标：

```bash
bash scripts/bootstrap-install.sh --platform trae --target-root /path/to/platform/skills
```

安装成功后，Agent 必须读取输出 `entry` 指向的 `SKILL.md`，再按该文件中的 WSL Supervisor 命令启动项目。安装器不会执行 `opencode auth`、不会写入 API Key，也不会修改模型配置。
