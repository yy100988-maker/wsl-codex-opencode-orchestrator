# WSL 版 2.1 优化方案与详细设计

> 版本：2.1-draft
> 日期：2026-08-22
> 状态：设计中
> 适用：wsl-codex-opencode-orchestrator（WSL 版）

## 1. 优化目标

在 2.0 稳定运行基础上，提升以下能力：

1. 内存压力自适应——接近阈值时自动降级并发
2. 孤儿进程定期扫描——父进程已死但子进程存活时自动回收
3. 进程健康监控——检测卡死、泄漏和无输出进程
4. WSL cgroup 内存限制——防止 WSL 消耗过多 Windows 内存
5. WSL 与 Windows 内存协调——双侧内存联动控制
6. 事件日志压缩——长时间运行后自动归档旧日志
7. worktree 空间回收——定期清理已完成任务的磁盘空间

## 2. 内存压力自适应

### 2.1 现状

当前内存控制是三段阈值，到达阈值后直接停止准入。WSL 版需要同时检查 WSL 和 Windows 双侧内存。

### 2.2 设计

#### 压力等级

```text
Pressure Level 0:  max(wsl_used, host_used) < 70%  → full concurrency
Pressure Level 1:  70% <= max < 80%  → reduce to 70%
Pressure Level 2:  80% <= max < 85%  → reduce to 40%
Pressure Level 3:  85% <= max < 90%  → reduce to 10%, kill highest-memory task
Pressure Level 4:  max >= 90%  → stop admission, kill top-2
```

#### 实现：memory-guard.sh

新增 `--mode adaptive-concurrency`：

```bash
adaptive_concurrency() {
  local used=$1 max=$2
  if (( used < 70 )); then echo "$max"
  elif (( used < 80 )); then echo $(( max * 70 / 100 ))
  elif (( used < 85 )); then echo $(( max * 40 / 100 ))
  elif (( used < 90 )); then echo $(( max * 10 / 100 ))
  else echo 0
  fi
}
```

#### 集成：admission-cycle.sh

```bash
wsl_used=$(free | awk '/Mem:/ {printf "%.0f", (($2-$7)/$2)*100}')
host_used=$(get_host_memory_percent)  # 通过 host-memory-guard.ps1 获取
max_used=$((wsl_used > host_used ? wsl_used : host_used))
effective_max=$(adaptive_concurrency "$max_used" "$max_concurrent")
slots=$((effective_max - active))
```

## 3. 孤儿进程定期扫描

### 3.1 现状

WSL 版通过 `process-manager.sh` 管理进程，但没有定期扫描孤儿进程。

### 3.2 设计

#### 实现：supervisor-loop.sh

```bash
scan_orphans() {
  local state="$1" root="$2"
  for record in "$root"/.opencode/processes/*.json; do
    [[ -f "$record" ]] || continue
    [[ "$(jq -r '.status // "running"' "$record")" == "running" ]] || continue
    local id=$(jq -r '.task_id' "$record")
    local pid=$(jq -r '.pid' "$record")
    if kill -0 "$pid" 2>/dev/null; then continue; fi
    # Root dead, find orphaned children
    local pgid=$(ps -o pgid= -p "$pid" 2>/dev/null | tr -d ' ')
    if [[ -n "$pgid" ]]; then
      ps -o pid= --pgid "$pgid" 2>/dev/null | while read -r child_pid; do
        child_pid=$(echo "$child_pid" | tr -d ' ')
        [[ -n "$child_pid" ]] || continue
        kill -TERM "$child_pid" 2>/dev/null || true
        wsl_append_event "$state" orphan-killed "$id" "{\"pid\":$child_pid}"
      done
    fi
    # Mark as recovered
    "$SCRIPT_DIR/process-manager.sh" stop "$state" "$id" >/dev/null || true
    wsl_append_event "$state" orphan-recovered "$id" '{"reason":"root-process-dead"}'
  done
}
```

#### 触发频率

每 5 轮 Supervisor 循环执行一次，可配置 `orphan_scan_interval`。

## 4. 进程健康监控

### 4.1 现状

WSL 版有 `stall_timeout` 和 `max_task_runtime_seconds`，但缺少 CPU/内存监控。

### 4.2 设计

#### 实现：process-manager.sh

新增 `health` 子命令：

```bash
process_health() {
  local pid_file="$1"
  local pid=$(jq -r '.pid' "$pid_file")
  local log=$(jq -r '.log // empty' "$pid_file")
  if ! kill -0 "$pid" 2>/dev/null; then
    echo '{"status":"dead"}'; return
  fi
  local mem=$(awk '/VmRSS/{print $2}' /proc/$pid/status 2>/dev/null || echo 0)
  local log_age=999
  [[ -f "$log" ]] && log_age=$(( ($(date +%s) - $(stat -c %Y "$log")) / 60 ))
  printf '{"status":"alive","memory_kb":%d,"log_age_minutes":%d}' "$mem" "$log_age"
}
```

## 5. WSL cgroup 内存限制

### 5.1 现状

WSL2 默认动态内存分配，可能消耗大量 Windows 内存。

### 5.2 设计

#### 运行时 cgroup 限制

```bash
ensure_cgroup_limit() {
  local config="$1"
  local limit_mb=$(jq -r '.memory.wsl_max_mb // 8192' "$config")
  local limit_bytes=$((limit_mb * 1024 * 1024))
  local current_max=$(cat /sys/fs/cgroup/memory.max 2>/dev/null || echo "max")
  if [[ "$current_max" == "max" || "$current_max" -gt "$limit_bytes" ]]; then
    echo "$limit_bytes" > /sys/fs/cgroup/memory.max 2>/dev/null || true
  fi
}
```

#### 集成：preflight.sh

Supervisor 启动时调用 `ensure_cgroup_limit`。

#### 配置

```json
{
  "memory": {
    "wsl_max_mb": 8192,
    "wsl_swap_mb": 2048,
    "cgroup_enabled": true
  }
}
```

## 6. WSL 与 Windows 内存协调

### 6.1 现状

当前只分别检查双侧内存，没有协调机制。

### 6.2 设计

#### 协调策略

```text
当 WSL 内存 > 80% 且 Windows 内存 > 70%:
  → WSL 降低并发到 50%
  → 通知 Windows 侧降低 MaxConcurrentAgents

当 Windows 内存 > 85% 且 WSL 内存 > 70%:
  → WSL 停止新任务准入
  → WSL 优先清理已完成任务的 worktree
```

#### 实现

`admission-cycle.sh` 在内存检查时同时读取双侧数据，取 `max(wsl, host)` 作为压力等级依据。

## 7. 事件日志压缩

### 7.1 现状

事件日志按日期存储，WSL 长时间运行后文件膨胀。

### 7.2 设计

#### 实现：common.sh

新增 `wsl_compress_events`：

```bash
wsl_compress_events() {
  local events_dir="$1" keep_days="${2:-7}" archive_days="${3:-30}"
  local keep_cutoff archive_cutoff
  keep_cutoff=$(date -d "-${keep_days} days" +%Y-%m-%d)
  archive_cutoff=$(date -d "-${archive_days} days" +%Y-%m-%d)
  for f in "$events_dir"/*.jsonl; do
    [[ -f "$f" ]] || continue
    local bn=$(basename "$f" .jsonl)
    if [[ "$bn" < "$archive_cutoff" ]]; then
      mkdir -p "$events_dir/../archives/events"
      mv "$f" "$events_dir/../archives/events/"
    elif [[ "$bn" < "$keep_cutoff" ]]; then
      jq -c 'select(.event_type | test("task-"))' "$f" > "$f.tmp" && mv "$f.tmp" "$f"
    fi
  done
}
```

#### 触发时机

Supervisor 启动时执行一次，之后每 100 轮执行一次。

## 8. worktree 空间回收

### 8.1 现状

WSL 版 worktree 在 Linux 文件系统中，磁盘空间更宝贵。

### 8.2 设计

#### 实现：worktree-manager.sh

新增 `disk-recovery` 子命令：

```bash
disk_recovery() {
  local root="$1" threshold_mb="${2:-1024}"
  local size_bytes=$(du -sb "$root/.opencode" 2>/dev/null | cut -f1)
  local threshold_bytes=$((threshold_mb * 1024 * 1024))
  (( size_bytes < threshold_bytes )) && return 0
  # Clean expired archives
  find "$root/.opencode/archives" -type f -mtime +30 -delete 2>/dev/null || true
  # Clean validated worktrees
  for wt in "$root/.opencode/worktrees"/*/; do
    [[ -f "$wt/.opencode-handoff.json" ]] && rm -rf "$wt"
  done
}
```

## 10. 验收标准

1. 双侧内存递增时，并发数平滑下降，无断崖
2. 孤儿进程在 5 轮 Supervisor 循环内被发现并清理
3. WSL 内存不超过 cgroup 配置上限
4. WSL 和 Windows 内存联动控制生效
5. 卡死进程在 10 分钟内被标记
6. 30 天以上的事件日志被自动压缩
7. `.opencode/` 目录超过 1GB 时自动清理
