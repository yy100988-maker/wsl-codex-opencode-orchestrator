# 运行机制

文档导航：[配置参考](配置参考.md) / `[[配置参考.md]]`， [任务协议](任务协议.md) / `[[任务协议.md]]`， [故障排查](故障排查.md) / `[[故障排查.md]]`。

## 角色边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| Codex 主控 | 读取设计、拆解任务、生成 prompt、监督、验收、合并、清理 | 把任务规划交给 OpenCode |
| WSL Supervisor | 预检、准入、启动、状态恢复、Gate 调用和回收 | 修改业务代码 |
| OpenCode 实现 agent | 单个任务的实现、测试、handoff 和任务分支提交 | 跨任务协调、合并、重新拆解 |
| 测试 agent | 运行测试和生成验收结果 | 修改业务代码、提交业务分支 |

## 一轮调度

1. Supervisor 获得项目单实例锁。
2. Bootstrap 自动安装固定系统依赖。
3. OpenCode Bootstrap 检测 Linux CLI；必要时删除当前用户的已确认 Windows wrapper，安装到 `~/.opencode/bin`，更新 `~/.profile` 并验证版本。
4. Preflight 检查发行版、项目根目录、Git、OpenCode、模型和路径。
5. 读取当前 active/history 和 Lease。
6. 检查依赖、文件重叠、并发上限和双层内存。
7. 为任务创建分支、worktree 和 prompt。
8. 使用 `setsid` 创建独立 OpenCode 进程组。
9. 记录 PID、PGID、启动时间、模型、日志和 worktree。
9. 进程退出后运行 Scope、Handoff、Static、Unit、Contract、Integration、Security Gate。
10. Gate 通过后由主控合并；失败任务进入 blocked 并归档 worktree。
11. 释放 Lease、停止进程组、记录事件并生成报告。

任务状态必须保持单一方向：`pending/waiting -> admitted -> running -> gate_pending -> done/blocked`。Supervisor 在启动前排除 active task，在任务退出后再执行 Gate；同一任务不得重复拥有 session、Lease 或 worktree。

## 模型回退

主模型为 `opencode-go/deepseek-v4-flash`。只有启动阶段发生模型不存在、provider 不可用或立即失败时，才允许回退一次到 `opencode-go/gpt-5.6-luna`。回退事件必须写入事件日志，备用模型失败后不得无限重试。

## 进程回收

清理流程：

1. 校验任务 PID、PGID 和启动时间。
2. 向任务 PGID 发送 SIGTERM。
3. 等待宽限期。
4. 仍存活时只向该 PGID 发送 SIGKILL。
5. 确认进程停止后再删除或归档 worktree。

禁止使用以下宽泛命令：

```bash
pkill node
pkill bun
pkill esbuild
```

## 恢复原则

Supervisor 重启后以状态文件、事件日志、进程记录、Lease 和 Gate 结果恢复。`handoff`、进程退出或测试通过中的任何一个单独条件，都不能直接把任务标记为最终完成。
